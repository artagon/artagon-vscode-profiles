## Contributing

Thanks for helping improve these VS Code profiles! This repository uses a vertical capability-module architecture compiled by portable Bash + `jq`.

### Prerequisites
- Bash (stock macOS or GNU Bash on Linux)
- `jq` installed
- Optional: VS Code CLI (`code`), `shellcheck`, `bats`, `zsh`, `fish`, `cargo` for full local verification

### Git Hooks (recommended)
Run the idempotent installer once after cloning:

```sh
bash scripts/install-hooks.sh
```

It sets `core.hooksPath = scripts/git-hooks` only when no other value is configured. The hook validates the repo and runs `vspcli build` without requiring the `code` CLI.

### Workflow
1. Edit source definitions under `catalog/`, `modules/`, or `profiles/<name>/profile.json`.
2. Rebuild compiled artifacts (`_merged/`, `profiles/*/`, `exports/`, 22 legacy symlinks, and `exports/SHA256SUMS`):
   - `bash scripts/vspcli build`
3. Refresh the generated `README.md` matrix if modules or profiles changed:
   - `bash scripts/generate-readme-matrix.sh --write`
4. Validate catalog, module DAG, collisions, scopes, and security invariants:
   - `bash scripts/vspcli validate`
5. Run the hermetic offline test suite:
   - `bash scripts/tests/run.sh`

### Architecture Rules
- Source of truth lives in `catalog/` (registries & pins), `modules/{capabilities,toolchains,ux}/` (vertical modules), and `profiles/<name>/profile.json` (thin recipes).
- Do not hand-edit `_merged/`, `profiles/*/extensions.json`, `profiles/*/settings.json`, or `exports/` — they are generated by `vspcli build`.
- Production scripts should remain portable across stock macOS and Linux Bash (zero Python/Node/Rust runtime dependencies).

### Commit Hygiene
- Group related changes and keep messages clear.
- Stage source edits together with their regenerated `_merged/`, `profiles/`, and `exports/` artifacts.
- Run `bash scripts/tests/run.sh` before opening a PR.
